# Lite AI Chat

一个面向低配 VPS 的轻量 AI 聊天网页，支持模型选择、登录认证、流式回答，以及真正独立于模型厂商的多轮外部搜索。

## 特性

- Groq Llama 3.3 70B、DeepSeek V4 Flash、DeepSeek V4 Pro 模型选择
- 外部 SearXNG 搜索层，不使用 DeepSeek 原生搜索
- 模型按需执行“分析结果 → 改写查询 → 再搜索”，最多五次外部检索
- 可选择普通思考或深度思考；普通模式使用更小的搜索和工具预算
- 回答内置可展开的“思考与工具”面板，可查看搜索关键词、工具状态及网页标题、链接和摘要
- 登录后可在网页填写 API Key、测试连接、读取并选择可用模型
- 每个账号保存最近 100 个服务器端对话窗口，历史每页显示 10 个，支持翻页、切换、新建和删除
- 回答在服务器后台生成，刷新、锁屏或关闭页面后仍会继续，重新打开即可恢复进度或查看结果
- 支持随时停止生成；会取消上游模型请求并保存已经生成的部分
- 内置安全 Markdown 渲染，支持表格、代码块、标题、列表、引用和链接
- 代码块右上角可一键下载，并根据语言自动选择常见文件扩展名
- 用户和助手消息均支持一键复制与从该处重新生成回答
- 每条消息最多上传 10 个图片/文件，原始附件合计不超过 50MB
- 图片经低内存缩放压缩后发送给视觉模型；PDF、DOCX、XLSX 和文本文件在本地限量提取文字
- 生成回答时不强制滚动；仅在发送消息且原本接近底部时跟随一次
- 搜索后可抓取关键网页正文，优先引用官方来源
- 首次访问创建管理员账号，此后关闭公开注册
- 管理员可在网页新增/删除普通账号，总账号数最多 3 个
- 普通账号无管理入口；各账号的对话、后台任务和登录权限相互隔离
- 内置低开销 HTTPS，自行生成本机 CA 和带 IP/DNS SAN 的服务器证书
- 单进程 FastAPI，适合小内存 Debian/Ubuntu VPS
- 安装服务仅开放聊天端口；SearXNG 只监听 `127.0.0.1:8888`

## 系统要求

- Debian 11/12 或 Ubuntu 20.04+
- root 或 sudo 权限
- 建议至少 512 MB 内存；更低内存机器应配置 Swap
- 至少一个 Groq 或 DeepSeek API Key
- 服务器可以访问 Docker Hub、模型 API 和搜索引擎

## 一键安装

```bash
git clone https://github.com/manatsu525/lite-ai-chat.git
cd lite-ai-chat
sudo bash install.sh
```

安装过程中会隐藏输入 Groq、DeepSeek API Key，两者均可留空，但至少配置一个才能正常聊天。默认 HTTPS 端口为 `8000`。

也可以非交互安装：

```bash
sudo GROQ_API_KEY='gsk_xxx' \
  DEEPSEEK_API_KEY='sk_xxx' \
  APP_PORT=8000 \
  TLS_HOST='服务器公网 IP 或域名' \
  bash install.sh
```

安装完成后访问：

```text
https://服务器IP:8000
```

第一次打开页面时创建管理员账号。

安装脚本会在 `data/tls/` 中生成一个本机 CA 和由其签发的服务器证书。首次访问会看到自签证书警告，可以临时选择继续访问；若希望长期消除警告，请只把 `/opt/lite-ai-chat/data/tls/ca.crt` 安装到手机或电脑的受信任 CA，切勿复制 `ca.key` 或 `server.key`。Android 通常在“安全 → 加密与凭据 → 安装 CA 证书”，iOS/iPadOS 安装描述文件后还需在“关于本机 → 证书信任设置”中启用完全信任。

证书会包含安装时检测到的服务器 IP；若机器有多个地址或使用域名，请通过 `TLS_HOST` 明确指定：

```bash
sudo TLS_HOST=66.59.198.186 bash install.sh
```

管理员登录后可点击右上角“账号管理”创建另外两个普通账号。删除普通账号会立即使其现有登录失效，并同时删除该账号的对话历史和后台任务。API Key 与可用模型由管理员统一配置，普通账号只能选择已配置模型，不能读取或修改密钥。

## 网页配置 API 与模型

登录后点击右上角的“API / 模型”：

1. 选择 Groq、DeepSeek 或其他 OpenAI 兼容接口。
2. 填写 API 地址和 API Key；已有密钥可留空继续使用。
3. 点击“测试 API 并读取模型”。
4. 从接口实际返回的模型列表中勾选需要显示的模型。
5. 保存后，聊天页的模型选择器会立即更新，无需重启服务。

密钥保存在服务器的 `data/providers.json`，权限为 `0600`。设置接口只返回密钥掩码，不会把完整密钥发送回浏览器。

取消勾选后保存可移除单个模型；点击“删除此 API 配置”可同时删除该提供商密钥和全部相关模型。

如果目标模型没有出现在 `/models` 返回结果中，可在“手动模型名”中每行填写一个模型。系统会直接向该模型发送最小聊天请求进行验证；即使提供商不支持 `/models`，手填模型验证成功后也可以保存。

### 自定义安装目录

```bash
sudo INSTALL_DIR=/opt/my-lite-ai-chat APP_PORT=9000 bash install.sh
```

升级时在仓库执行 `git pull`，然后重新运行安装脚本。已有 `.env` 和用户数据会保留。

## 外部多轮搜索

所有可选模型都调用同一个 `web_search` 工具：

1. 模型生成第一条查询。
2. 本机 SearXNG 聚合外部搜索引擎并返回结果。
3. 模型判断信息是否充分；不足时使用年份、官网域名或 `site:` 改写查询。
4. 深度思考最多执行五次不同搜索、每次最多十条结果，并可抓取具体网页。
5. 当前模型基于工具结果组织最终答案和来源。

DeepSeek API 在本项目中只负责模型推理，不会调用 DeepSeek 原生搜索。

聊天页可选择两档思考深度。深度思考保持完整预算：最多 5 次搜索、每次 10 条结果和现有最多 10 轮工具循环。普通思考由后端硬限制为最多 3 次搜索、每次 5 条结果、所有工具累计最多调用 6 次；即使模型一次请求更多结果或并行发出更多工具，也会在执行前被裁剪。该选项只调整本项目的外部搜索与工具预算，不擅自修改模型回答的详细程度。

生成期间，“思考与工具”面板会按阶段显示当前状态，并记录每次搜索或网页读取。面板及其中的单个网页结果都可以展开/收起；搜索结果只保存有限长度的标题、链接与摘要，抓取正文只保留最多 2,000 字符的展示摘录。过程记录随后台任务和对话历史保存，因此刷新、锁屏或回答完成后仍可查看。界面展示的是可核验的执行阶段和工具数据，不保存模型不可控的逐字内部推理链。

知乎、百度搜索（`www.baidu.com/s`）、百度贴吧、抖音、头条、小红书、什么值得买等站点经 VPS 实测会要求验证、返回 403，或只返回依赖 JavaScript 的页面空壳。项目不会为此在低内存机器上常驻 Chromium：普通 HTTP 失败后会用 `curl_cffi` 模拟 Chrome 的 TLS/HTTP2 指纹重试；提示词和工具说明同时优先引导模型选择可公开读取的来源，模型仍选择已知强反爬域名时，后端会改抓同一轮搜索中尚未使用的公开候选，并在过程面板明确记录来源替换。百度百科（`baike.baidu.com`）、百度文库（`wenku.baidu.com`）及其他未明确阻断的页面不在固定避开范围内，会按普通网页正常尝试抓取；百度文库的可读范围可能因具体文档而异。若替代来源仍失败，则复用对应搜索结果的标题与索引摘要并标记为“非网页全文”。没有可用摘要时会如实返回源站限制，不会伪造正文。

网页 HTML 不再直接从开头转文字后裁剪。内置抓取先限制原始响应体大小，再使用 `readability-lxml` 选择正文节点、删除导航/广告/相关推荐和重复短行，最后才应用 8,000 字符正文上限；如果页面 HTML 只有标题和导航、正文必须由 JavaScript 加载，会判定为无可用正文并进入下一层降级，而不会用导航链接填满上下文。过程面板会显示实际抓取方式和正文提取方式。

MediaWiki 页面使用独立提取路径：优先读取 `mw-content-text`，保留普通表格的单元格边界和图片 `alt/title` 信息；对于用绝对坐标与图片绘制的视觉数据表，会按行列位置还原为 Markdown 表格。这样建筑名、兵种名、资源图标与数值不会在纯文本转换时脱离对应关系。

为控制上下文和 API token 消耗，搜索摘要每条最多保留 500 字符，单个网页正文最多保留 8,000 字符；每个回答最多深入抓取 5 个网页，工具结果在当前上下文中的总量最多为 60,000 字符。超过总预算后会优先压缩最旧结果，只保留标题、URL 和关键结论/摘录。模型只携带最近 10 轮完整对话，更早消息会在本地压缩为最多 6,000 字符的摘要，不会额外调用模型做摘要。

所有模型提供商的单轮响应和手填模型验证超时统一为 20 分钟，适合首 token 较慢的 Agnes 等 OpenAI 兼容接口。聊天任务由服务器执行，页面只轮询任务状态，因此网络短暂中断、刷新页面、锁屏或关闭浏览器不会取消生成。服务进程重启仍会中断当时正在运行的任务，已完成和已停止的回答会保留在对话历史中。

## 图片与文件

点击输入框左侧的“＋”可以选择多个附件。每条消息最多 10 个，所有原始附件合计最多 50MB。为了适配小内存 VPS，浏览器逐个上传文件，服务器以数据流方式落盘，不会一次读入 50MB；原文件处理后立即删除：

- JPG、PNG、WebP、GIF、BMP：只处理第一帧，最多约 1600 万像素，缩放到最长边 1600 像素并压缩到最多约 1.5MB。图片会通过 OpenAI 兼容的 `image_url` 数据格式发送，因此必须选择真正支持视觉输入的多模态模型；普通文本模型拒绝图片时，页面会明确提示换模型。
- PDF：使用受 96MB 地址空间、35 秒 CPU 时间和 45 秒墙钟时间限制的 `pdftotext` 子进程，最多提取前 30 页、每个文件最多 30,000 字符。扫描版 PDF 不做 OCR。
- DOCX、XLSX：直接读取压缩包内 XML，不启动 LibreOffice；XLSX 最多读取前 5 个工作表和每表 2,000 行。复杂排版、公式计算、图表和宏不会还原。
- 常见文本、Markdown、CSV、JSON 和代码文件：按文本读取。旧版 `.doc`、`.xls` 需要先另存为 `.docx`、`.xlsx`。

一次回答中的全部文档摘录最多 80,000 字符。附件只用于本次生成，任务完成或停止后立即删除；未发送的附件 24 小时后清理。历史记录会保留附件名称，但为了控制磁盘与隐私，不会永久保存附件本体，因此从历史点击“重新回答”不会重新附带原文件。

服务器会串行处理图片，并且同一时间只运行一个带附件的模型任务，防止三个账号同时解码图片或构造 Base64 请求时超过 `MemoryMax=150M`。因此多人同时发送附件时，后提交的任务会短暂显示“正在等待附件任务”，这是这类 300MB 级 VPS 上有意采用的稳定性取舍。

数据采用双重限额：每次保存时立即把每个账号的对话窗口裁剪到最近 100 个，前端历史每页只读取 10 个标题，并按需读取当前对话正文。后台还会在启动时及每 30 天重新检查一次，并同步清理已淘汰窗口的已完成任务、孤立记录、过期附件和每个账号超过 30 条的旧任务。SQLite 文件至少达到 1 MiB 且空闲页超过 25% 时才执行 `VACUUM`，避免低配机器频繁压缩数据库。

## 卸载

安全卸载会先把 `.env` 和用户数据库备份到 `/var/backups/`：

```bash
sudo bash uninstall.sh
```

彻底卸载且不保留备份：

```bash
sudo bash uninstall.sh --purge
```

卸载脚本不会删除系统 Docker、Python 或其他项目共用的软件包。

## 安全提示

- 不要提交 `.env`、数据库或真实 API Key。
- HTTPS 由现有 Uvicorn 进程直接提供，不额外运行 Nginx/Caddy；仍建议用防火墙限制聊天端口。
- 只分发 `ca.crt`，绝不要把 `data/tls/` 中的任何私钥复制到客户端。
- SearXNG 默认仅绑定本机，切勿无认证直接暴露到公网。
- 如果服务器已经被公网扫描，建议更换强管理员密码并启用 HTTPS。
